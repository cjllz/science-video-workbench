# Script Overview and Material Variables Design

## Goal

Change the science-video workbench from immediate generation into a confirmable workflow:

`define video or import script -> generate/parse storyboard -> review script -> upload materials -> reference materials with @variables -> confirm -> generate video -> revise individual results`

The first release must support AI-authored scripts, pasted scripts, TXT/Word imports, images, video, audio, CSV/XLSX data, editable shots, material variables, and an explicit confirmation gate before paid video generation.

## Product Flow

1. The user enters a topic and optional brief, pastes a script, or imports TXT/DOCX.
2. DeepSeek creates or structures a `VideoPlan` without starting video generation.
3. The job enters `awaiting_confirmation` and opens the script overview.
4. The user edits shot order, duration, headline, narration, and visual direction.
5. The user uploads materials. Each upload receives an editable, human-readable variable such as `@血压监测仪` or `@七日血压数据`.
6. The user inserts variables into a shot's visual direction through autocomplete or the material picker.
7. Each variable reference is configured with a role and mode:
   - image: subject, scene, first frame, last frame, replacement, or overlay
   - video: motion, camera, scene, edit source, or extension source
   - audio: voice, music, rhythm, or sound reference
   - data: deterministic chart
8. Preflight validates unresolved variables, duplicate names, unsupported provider inputs, invalid chart fields, shot timing, and total duration.
9. Confirmation persists the edited plan and bindings, then starts paid generation.
10. Seedance generates eligible backgrounds/shots; deterministic rendering composites exact device images and charts; controlled narration and captions are added last.

## Data Model

`VideoJob` gains `awaiting_confirmation` and `confirmed` lifecycle semantics. Planning and rendering are separate queue actions.

`MaterialAsset` stores:

- stable ID and editable variable name
- kind: image, video, audio, or data
- original filename, MIME type, local storage path metadata, size, and creation time
- optional dimensions/duration and optional public URL
- parsed `DataAsset` metadata for CSV/XLSX

`ShotMaterialBinding` stores:

- material ID and variable name
- role and render mode
- optional start/end offset within the shot
- optional placement
- optional chart configuration

`ShotPlan` stores `materialBindings`. The human-facing visual direction contains `@variable` tokens, but generation uses stable material IDs from bindings. Renaming a variable updates display text without changing identity.

## API

- `POST /api/script-imports`: parse TXT, MD, or DOCX and return text.
- `POST /api/materials`: upload image, video, audio, CSV, or XLSX and return `MaterialAsset`.
- `GET /api/materials`: list uploaded material assets.
- `POST /api/jobs`: create a job and enqueue planning only.
- `PATCH /api/jobs/:id/plan`: save edited plan and material bindings while awaiting confirmation.
- `POST /api/jobs/:id/render`: run preflight, mark confirmed, and enqueue rendering.

Existing completed jobs remain readable. Existing `/api/uploads` data upload remains temporarily compatible.

## Provider Mapping

The Ark adapter converts internal variables to provider references in content order:

- image variables become `@图片1`, `@图片2`, and `image_url` entries
- video variables become `@视频1` and `video_url` entries
- audio variables become `@音频1` and `audio_url` entries
- first/last-frame roles map to provider roles instead of generic references
- exact overlays and data charts are removed from the Seedance prompt and handled locally

Local uploads are always usable for deterministic composition. AI reference mode requires a provider-readable representation. Images will first attempt an accepted data URL; public URLs remain supported for larger video/audio assets. Unsupported references fail preflight instead of being silently ignored.

## Rendering Rules

- Device and product images default to exact overlay when visual identity must remain unchanged.
- AI reference mode is available when natural interaction matters more than pixel-perfect details.
- Data values are never generated by Seedance. CSV/XLSX fields are rendered into SVG/chart frames from parsed source values and composited at the configured placement.
- Narration remains independent TTS for medical wording control. Seedance native audio stays disabled by default.
- Missing or rejected AI assets fall back per shot without discarding the confirmed script.

## UI

The workbench has three states:

1. Define: topic, style, script source, and plan generation.
2. Review: script overview, material library, variable insertion, binding settings, preflight, and confirm button.
3. Generate/result: progress, video, storyboard, history, and feedback.

The review view uses editable shot cards. Each card contains narration and visual direction fields plus material chips. Typing `@` or selecting "insert material" inserts a variable. Clicking a chip opens role/mode/placement settings.

## Error Handling

- Invalid imports return a Chinese error without creating a job.
- Upload limits are enforced per MIME type and total size.
- Unresolved `@variables` block confirmation and identify the affected shot.
- Removed materials leave an explicit unresolved binding rather than silently changing the prompt.
- Rendering can only start from `awaiting_confirmation` or a failed confirmed render.
- Duplicate render requests are idempotently rejected while a job is active.

## Verification

- Unit tests cover variable extraction/rewrite, upload classification, DOCX/TXT parsing, preflight, database persistence, and Seedance request mapping.
- API tests cover plan-only creation, plan editing, invalid variables, and render confirmation.
- Existing planner, data, shot policy, and build tests remain green.
- Browser verification covers AI script creation, pasted/imported script, material upload, variable insertion, plan editing, confirmation, and progress transition.
- A real Ark image-reference probe determines whether data URLs are accepted. The UI communicates the result and requires a public URL for unsupported media.
